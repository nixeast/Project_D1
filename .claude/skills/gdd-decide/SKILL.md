# GDD 기획 결정 절차

브론즈가드 GDD 정리 단계(1단계)에서 열린 항목 하나를 결정하고 문서에 반영합니다. 인자로 항목 번호(예: `D9`)를 받습니다. 없으면 다음 항목을 고릅니다.

## 1. 항목 확인 (토큰 절약)

- 남은 항목은 `python tools/gdd.py status`로 확인합니다. 99번 문서 전체를 읽지 않습니다.
- 항목 행만 확인합니다: Grep `^\| D9 \|` in `docs/GDD/99_review_notes.md`
- 관련 챕터는 **필요한 절만** 읽습니다. 먼저 `grep -n "^#"`로 제목을 보고 `sed -n`으로 해당 범위만 읽습니다.
- 시스템 연결은 `docs/GDD/01_overview.md` §5 시스템 구조를 봅니다.
- `05a_events.md`(이벤트 원고)와 `98_decision_log.md`(결정 기록)는 필요할 때만 Grep으로 찾아봅니다.

## 2. 문답

- AskUserQuestion으로 한 번에 **최대 4문항**을 묻습니다. 추천안을 첫 번째에 두고 라벨 끝에 "(추천)"을 붙입니다.
- 질문에는 판단에 필요한 맥락(현재 규칙, 코드 임시값, 관련 결정)을 한 줄 넣습니다.
- 추천안이 아닌 답이 나와 세부가 생기면 2차 문답을 합니다.
- 수치는 "초기값"으로 정하고, 세부 수치와 목록은 게임 데이터에 둔다고 적습니다(GDD에는 규칙과 의도만).
- 사용자가 묻지 않았지만 제가 정한 기본값이 있으면 마지막 보고에 따로 밝힙니다.

## 3. 문서 반영

1. **해당 챕터**에 규칙을 씁니다. 한 사실은 한 곳에만 두고, 다른 챕터에서는 링크로 참조합니다.
2. **영향받는 챕터**(03 캠페인, 05 탐사, 06 전투, 07 유닛 등)의 문구를 맞춥니다.
3. **01 §5 시스템 구조**에서 해당 `**미정 (D#)**` 표시를 고치고, §5.4 '빈 곳'을 갱신합니다.
4. **99·98 갱신**은 스크립트로 합니다.
   ```
   python tools/gdd.py decide D9 --title "모병소 갱신" --before "이전 상태" --after "결정 요약"
   ```
   - 99번에서 행을 지우고, 98번 §1 표 끝에 오늘 날짜로 기록합니다. `--dry-run`으로 먼저 확인할 수 있습니다.
   - 결정 과정에서 새 열린 항목이 생기면 99번의 알맞은 묶음에 새 D 번호로 추가합니다.
5. **링크 검사**: `python tools/gdd.py links`
6. 단계가 바뀌거나 큰 합의가 생겼을 때만 `progress.md` 작업 기록에 한 줄 남깁니다.

## 4. 편집 요령

- 여러 파일을 고칠 때는 짧은 Python 스크립트로 정확한 문자열을 바꿉니다(`assert s.count(old)==1`). 원래 줄바꿈(CRLF/LF)을 유지합니다.
- 앵커는 GitHub 방식입니다: 소문자, 글자·숫자·`-`·`_`·공백만 남기고 공백은 `-` (예: `### 1.3 쓰러짐·부상·회복` → `#13-쓰러짐부상회복`).

## 5. 마무리

- 결정 내용, 고친 문서, 제가 정한 기본값, 새로 보인 문제를 짧게 보고합니다.
- 결정 하나를 반영하면 묻지 않고 현재 작업 파일만 커밋하고 현재 브랜치로 푸시합니다(강제 푸시 금지).
- 코드·씬·CSV·그래픽은 수정하지 않습니다(사양서 확정 전).
